What Is a DHCP Lease?

concept
📖 What to Read & Display on Screen

A lease grants temporary use of an address supplied by Dynamic Host Configuration Protocol. The server also provides options such as mask, gateway, and name resolver.

  • A pool is the set of available addresses. Exclusions and reservations keep infrastructure addresses under control.
  • A lease grants temporary use; Dynamic Host Configuration Protocol (DHCP) also supplies options such as subnet mask, gateway, and Domain Name System (DNS).
  • A server must avoid duplicate active assignments. Clients and servers also use conflict detection in real deployments.

Four messages in the initial DHCP exchange

concept
📖 What to Read & Display on Screen

Initial allocation commonly follows Discover, Offer, Request, and Acknowledgment. These messages locate a server, propose settings, select an offer, and confirm the lease.

  • Discover: the client seeks Dynamic Host Configuration Protocol (DHCP) servers.
  • Offer: a server proposes an available address and configuration options.
  • Request: the client identifies the chosen offer and requests its configuration.
  • Acknowledgment (ACK): the server confirms the lease, after which the client can use the configuration.

🗣️ How to Explain It (Talking Points)

  • Request: the client identifies the chosen offer and requests its configuration.
  • Acknowledgment (ACK): the server confirms the lease, after which the client can use the configuration.
  • Initial discovery uses broadcast.
  • Some replies can be unicast depending on client state; DORA is an introduction to a richer state machine.

Example: a laptop receives a lease

example
📖 What to Read & Display on Screen

A new laptop can obtain address settings from an available configuration server. The confirmed lease must use an address that does not conflict with another active allocation.

  • The laptop discovers the service, receives an offer for 192.168.1.100, requests it, and receives an acknowledgment committing the lease.
  • The server also supplies subnet mask, gateway, resolver information, and lease lifetime. Another active client must receive a different available address.

Five lease lifecycle and failure events

concept
📖 What to Read & Display on Screen

Leases can be renewed, released, or allowed to expire. Unavailable servers and exhausted pools create different failures even when the client’s physical connection works.

  • Renewal: requests an extension from the existing server; it need not repeat the initial full Discover, Offer, Request, Acknowledge (DORA) exchange.
  • Release: returns the address to the server.
  • Expiry: makes an unrenewed lease available again.
  • Pool exhaustion: no unused address is available for another client.
  • Server unavailable: a client may eventually self-assign link-local configuration without ordinary routed access.

Reading a DHCP Lease Configuration

walkthrough
📖 What to Read & Display on Screen

Automatic configuration includes more than a host address. Lease lifetime, gateway, resolver, and server information help explain which settings the client received.

  • An authorized router pool contains usable addresses inside its Local Area Network (LAN) subnet, excluding the router and other managed infrastructure.
  • A client set to automatic Internet Protocol (IP)/Domain Name System (DNS) obtains address, mask, gateway, DNS, and a lease lifetime from the reachable server.
  • Discover locates a server, Offer proposes configuration, Request selects it, and Acknowledgment (ACK) commits the lease.
  • On authorized Windows equipment, ipconfig /all shows Dynamic Host Configuration Protocol (DHCP) and lease information; ipconfig /release and ipconfig /renew return and request configuration.
  • Pool exhaustion, unavailable service, conflicting options, and invalid pool boundaries are different faults. An unapproved Dynamic Host Configuration Protocol (DHCP) server must not be attached to the production Local Area Network (LAN).

Thirty laptops join a lab

application
📖 What to Read & Display on Screen

A working wireless connection does not guarantee an available address lease. When client demand exceeds the free pool, some clients cannot obtain the intended configuration.

  • Some new clients cannot obtain an address even though their Wi-Fi association succeeds.
  • Inspect pool capacity and active leases before replacing cables.
  • An unauthorized second Dynamic Host Configuration Protocol (DHCP) server can supply conflicting options; keep the lab isolated.
