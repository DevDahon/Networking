Three Core Terms: Protocol, Service, Port

concept
📖 What to Read & Display on Screen

A protocol defines exchange rules, a service provides a useful function, and a transport port acts like an apartment door number directing traffic to a specific application process.

  • Protocol: agreed message formats and behavior, such as Domain Name System (DNS) queries and replies.
  • Service: a useful function provided by a running system, such as a Domain Name System (DNS) resolver answering names.
  • Port: a Transmission Control Protocol (TCP) or User Datagram Protocol (UDP) endpoint number used to direct traffic to a process; it is not a physical Ethernet socket.
💡 Brief Explanation After Reading (Teacher's Discussion Notes)

🌟 Real-World Analogy / Intuition

A classroom laptop obtains configuration, looks up the school server, downloads a protected handout, and connects securely via SSH.

🗣️ How to Explain It (Talking Points)

  • Protocol: agreed message formats and behavior, such as DNS queries and replies.
  • Service: a useful function provided by a running system, such as a DNS resolver answering names.
  • Port: a TCP or UDP endpoint number used to direct traffic to a process; it is not a physical Ethernet socket.
  • A familiar port suggests a convention; it does not prove which program is listening or whether that program is safe.

Four TCP/IP responsibility groups

concept
📖 What to Read & Display on Screen

The common Transmission Control Protocol (TCP)/Internet Protocol (IP) model groups network functions into four responsibility areas. Application services depend on transport, Internet delivery, and local-link functions.

  • Application: Dynamic Host Configuration Protocol (DHCP), Domain Name System (DNS), Hypertext Transfer Protocol (HTTP), Hypertext Transfer Protocol Secure (HTTPS), and Secure Shell (SSH) provide user-facing and network configuration services; commonly associated with Open Systems Interconnection (OSI) 7.
  • Transport: Transmission Control Protocol (TCP) and User Datagram Protocol (UDP) use process ports; commonly associated with Open Systems Interconnection (OSI) 4.
  • Internet: Internet Protocol (IP) supplies logical delivery and Internet Control Message Protocol (ICMP) supplies related diagnostics; commonly associated with Open Systems Interconnection (OSI) 3.
  • Link: local framing and physical transmission; Address Resolution Protocol (ARP) supports Internet Protocol version 4 (IPv4) neighbor resolution at this local-link boundary.
💡 Brief Explanation After Reading (Teacher's Discussion Notes)

🌟 Real-World Analogy / Intuition

A classroom laptop obtains configuration, looks up the school server, downloads a protected handout, and connects securely via SSH.

🗣️ How to Explain It (Talking Points)

  • Application: DHCP, DNS, HTTP, HTTPS, and SSH provide user-facing and network configuration services; commonly associated with OSI 7.
  • Transport: TCP and UDP use process ports; commonly associated with OSI 4.
  • Internet: IP supplies logical delivery and ICMP supplies related diagnostics; commonly associated with OSI 3.
  • Link: local framing and physical transmission; ARP supports IPv4 neighbor resolution at this local-link boundary.
  • OSI/TCP-IP mappings are approximate.
  • Advanced enterprise protocols like SNMP, NTP, and dedicated mail servers are studied in Networking II.

Two transport services: TCP and UDP

concept
📖 What to Read & Display on Screen

Transmission Control Protocol supplies ordered reliable bytes, while User Datagram Protocol carries independent datagrams without built-in delivery guarantees. Their differences affect how application protocols handle communication.

  • Transmission Control Protocol (TCP): connection-oriented, ordered reliable bytes, with acknowledgments and retransmission. Useful when the application needs this stream service.
  • User Datagram Protocol (UDP): connectionless datagrams without built-in delivery or ordering guarantees. Useful when a small exchange or application-controlled behavior fits the task.
💡 Brief Explanation After Reading (Teacher's Discussion Notes)

🌟 Real-World Analogy / Intuition

A classroom laptop obtains configuration, looks up the school server, downloads a protected handout, and connects securely via SSH.

🗣️ How to Explain It (Talking Points)

  • TCP: connection-oriented, ordered reliable bytes, with acknowledgments and retransmission.
  • Useful when the application needs this stream service.
  • UDP: connectionless datagrams without built-in delivery or ordering guarantees.
  • Useful when a small exchange or application-controlled behavior fits the task.
  • Neither “UDP is always faster” nor “TCP proves the application processed the request” is a reliable conclusion.
  • Application protocols can add recovery above UDP.

Client and Server Endpoints

concept
📖 What to Read & Display on Screen

A client commonly uses a temporary source port to contact a server’s listening port. Addresses, ports, and transport together identify the communication context.

  • A normal client often uses a temporary source port, such as Transmission Control Protocol (TCP) 53001, to contact a server listening on TCP 443. The response returns to that client endpoint.
  • The connection context includes transport plus source/destination addresses and ports. Transmission Control Protocol (TCP) and User Datagram Protocol (UDP) can use the same numeric port independently.
  • System ports are 0–1023, user/registered ports 1024–49151, and dynamic/private ports 49152–65535. Port 0 is reserved; operating systems may choose temporary ports from implementation-specific ranges.
  • A reachable Internet Protocol (IP), an open transport endpoint, Transport Layer Security (TLS) validation, and a working application are separate observations. Testing one does not prove all the others.

Internet Protocol (IP)

concept
📖 What to Read & Display on Screen

Internet Protocol supplies logical addressing and packet delivery across networks. It provides best-effort delivery rather than an ordered reliable application stream.

  • Practical application: Internet Protocol version 4 (IPv4) or Internet Protocol version 6 (IPv6) identifies source/destination interfaces and supports router forwarding.
  • Internet Protocol (IP) provides best-effort delivery, not a reliable application byte stream. It has no Transmission Control Protocol (TCP)/User Datagram Protocol (UDP) port. Internet Protocol version 6 (IPv6) uses 128-bit addresses and does not use Address Resolution Protocol (ARP).

Address Resolution Protocol (ARP)

concept
📖 What to Read & Display on Screen

Address Resolution Protocol resolves the hardware address of an Internet Protocol version 4 (IPv4) next hop on a local link. A remote destination usually requires the gateway’s local hardware address rather than the remote host’s.

  • Practical application: Find a local peer’s Ethernet Media Access Control (MAC), or the gateway MAC when sending toward a remote Internet Protocol (IP) network.
  • Address Resolution Protocol (ARP) is not carried inside Transmission Control Protocol (TCP) or User Datagram Protocol (UDP) and has no port. Ethernet ARP uses EtherType 0x0806. Routers do not forward a local ARP broadcast across Internet Protocol (IP) networks; Internet Protocol version 6 (IPv6) uses Neighbor Discovery instead.

ICMP and Network Ping Basics

concept
📖 What to Read & Display on Screen

Internet Control Message Protocol carries diagnostic and error information related to Internet Protocol delivery. Echo messages and expiry reports provide evidence without proving that every application service works.

  • Practical application: Ping commonly uses Echo; traceroute-style tools use Time to Live (TTL)/hop-limit behavior and returned diagnostics.
  • Internet Control Message Protocol (ICMP) has no Transmission Control Protocol (TCP)/User Datagram Protocol (UDP) port. ICMP for Internet Protocol version 4 (IPv4) uses Internet Protocol (IP) protocol number 1; Internet Control Message Protocol for IPv6 (ICMPv6) uses next-header 58. Missing replies may mean filtering or loss. It does not fix a failed link.

Domain Name System (DNS)

concept
📖 What to Read & Display on Screen

The Domain Name System answers queries about names using records such as host addresses and mail destinations. Name resolution supplies information for later communication rather than carrying the application traffic itself.

  • Practical application: Find the address for a school web or mail server by name.
  • Classic Domain Name System (DNS) supports User Datagram Protocol (UDP) and Transmission Control Protocol (TCP) on port 53. TCP is not limited to zone transfers: it also supports other queries, including fallback after truncation. Caches respect record lifetimes. Encrypted DNS has additional transports.
  • User Datagram Protocol (UDP) 53: Classic Domain Name System (DNS) queries/responses.
  • Transmission Control Protocol (TCP) 53: Classic Domain Name System (DNS) over a TCP connection.

Hypertext Transfer Protocol (HTTP)

concept
📖 What to Read & Display on Screen

Hypertext Transfer Protocol defines requests and responses for web resources. Methods, status codes, and message content describe the requested operation and its result.

  • Practical application: A browser requests a page or a client calls a web Application Programming Interface (API).
  • Ordinary Hypertext Transfer Protocol (HTTP) does not provide Transport Layer Security (TLS) encryption. HTTP/1.1 commonly uses Transmission Control Protocol (TCP); port 80 is the conventional HTTP service endpoint. An HTTP status error differs from a failure to reach the server.
  • Transmission Control Protocol (TCP) 80: Conventional unencrypted Hypertext Transfer Protocol (HTTP) service.

HTTPS and Secure Web Browsing

concept
📖 What to Read & Display on Screen

Hypertext Transfer Protocol Secure protects web communication using Transport Layer Security. Certificate validation and authenticated encryption protect the connection without guaranteeing that the website’s content is trustworthy.

  • Practical application: Access a protected classroom portal without exposing application content on the local path.
  • Hypertext Transfer Protocol (HTTP)/1.1 and HTTP/2 commonly use Transport Layer Security (TLS) over Transmission Control Protocol (TCP) 443. HTTP/3 uses QUIC with TLS security over User Datagram Protocol (UDP), commonly 443. Hypertext Transfer Protocol Secure (HTTPS) does not prove a site is trustworthy or hide every piece of network metadata.
  • Transmission Control Protocol (TCP) 443: Hypertext Transfer Protocol Secure (HTTPS) using Hypertext Transfer Protocol (HTTP)/1.1 or HTTP/2.
  • User Datagram Protocol (UDP) 443: Hypertext Transfer Protocol (HTTP)/3 over QUIC; common Hypertext Transfer Protocol Secure (HTTPS) endpoint.
